The heap's last slot stays null (out of title slots, dynamic slots, copy-back pairs via `pairs_end`), so past-cap indices read nothing instead of faulting. The cap joins the shader-cache key (`shader_cache.rs::build()` initializes the host first).
- Ported as fork PR #11 (branch new-cap, commit b8388e9d, CI 45545098162 green, mergeable CLEAN). Guard arithmetic: when `cap == Some(count + DYNAMIC)` (or `+MIN_DYNAMIC`), the matching `.max(views)` rung always succeeds first, so the plain rungs can never hide a needed guard trim.

## Device removal at world entry: sampler heap never bound (fixed 2026-11-25, commit 363d19d)

- Root cause pinned from the log excerpts: D3D12 debug-layer message **id=1419** — `SetComputeRootSignature: SetDescriptorHeaps must be called to bind a sampler descriptor before setting a root signature with D3D12_ROOT_SIGNATURE_FLAG_SAMPLER_HEAP_DIRECTLY_INDEXED`. Every host pipeline's root signature carries that flag unconditionally (`victory-gpu/src/pipeline/host.rs` root_signature ~line 807, and `victory-shader/src/emit/host.rs:280` for the emit test harness), but `State::bind_heaps` (`victory-gpu/src/draw.rs:836`) bound a sampler heap only when the title had bound one (heaps[1]) whose host copy already existed. With no sampler heap bound: (a) the root-signature set is an invalid call (id=1419, fired at 04:54:35.339 in run 2 with DEBUG on), (b) a translated shader reading `SamplerDescriptorHeap` (SM 6.6 heap-directly-indexed sampling) faults the GPU — run 1's removal 0x887A0001 "after a submission of 1 lists" ~56 s in at world entry (first sampler-heap reads through newly bound pipelines), no breadcrumbs because debug was off.
- The internal HLSL helpers (indirect clamp, twin depth converter, memory prelude, bindless test) embed plain HLSL root signatures (no heap-directly-indexed flags) — never the id=1419 source. The FidelityFX external module sets its own heaps before its root signature (and host_state_lost rebinds after).
- Fix: `descriptor::host::sampler_heap()` (new, descriptor/host.rs after null_sampler) — OnceLock'd shader-visible SAMPLER heap of `HEAP_SAMPLERS` (2048) slots, every slot a plain point-clamp sampler (translated shaders clamp sampler indices below HEAP_SAMPLERS, so every read lands in-bounds; undescribed slots read null, same contract as the view heaps). `bind_heaps` now always binds a sampler heap: the title's host copy when it exists (heap key in host_heaps[1]), else ours (sentinel `OUR_SAMPLERS = usize::MAX - 1`, distinct from `MEMORY_HEAP` = usize::MAX and the `host_state_lost` reset sentinel [usize::MAX; 2]); rebinds when the title's host copy appears later. ## Run 3 (no debug layer) root cause: B4G4R4A4_UNORM render target (2026-11-25)

- The removal reproduced WITHOUT the debug layer (run 3, 06:03:07.257, same 0x887A0001 after 1 list, ~0.8 s after the precursor) — so id=1419 was a real invalid call but not the only one. The precursor in BOTH runs, <1 s before removal: `the host refuses castable formats` → `no host texture` for a 2560×1440 texture, format 115, flags 1.
- Format **115 = DXGI_FORMAT_B4G4R4A4_UNORM** (windows crate Dxgi::Common; 2 bytes/texel, so it is in `element()`'s 2-byte arm). `flags: 1` in victory's ResourceDesc numbering = ALLOW_RENDER_TARGET. D3D12 does not allow render targets in B4G4R4A4 → `CreateCommittedResource3` (castable path, ID3D12Device10) AND the plain `CreateCommittedResource` fallback both E_INVALIDARG → `resource(this).host = None` → the memory has NO host texture; every consumer guards on None (set_targets continue, clear_rtv return, copies skip, SRV null), and the device still removed shortly after.
- Fix (commit 5ecd621, CI 45560228903 green): `resource::supported_flags(format)` — cached `D3D12_FEATURE_FORMAT_SUPPORT` query (RT bit 1, UAV bit 4 of the console flag numbering); `host_desc` drops RT/UAV bits the format cannot serve so the texture is made (flagless). Guards: `draw.rs set_targets` and `list.rs clear_rtv` skip targets/clears whose host texture lacks `D3D12_RESOURCE_FLAG_ALLOW_RENDER_TARGET` (once-warn naming the format). `descriptor::host::typed_store` now delegates to `supported_flags`. Details: typeless formats (family-head test `typeless(format)`) keep their flags (they serve what the family does); the host takes RT or depth, never both, so depth textures lose the RT bit; the optimized clear value is only passed when flags still include RT or depth (D3D12 refuses a clear value on a flagless resource — would have been the NEXT E_INVALIDARG).
- `cargo fmt -p` trap confirmed AGAIN: it reformatted 21 files (+2239/−538) even with file args, because the tree is not rustfmt-clean under rustfmt.toml and CI runs no fmt gate. Recovery: `git checkout -- crates/victory-gpu/src/` then re-applied the semantic hunks by hand (+99/−26 final). Never commit fmt churn.
- Expected next run: the B4G4R4A4 texture exists (log line `texture 2560x1440 f115 flags 0` in the host name tag); warn `a render target the host cannot render to` (or `... clear ...`) appears once; no `no host texture` for it; if the removal persists WITH VICTORY_D3D12_DEBUG=1 the debug layer now names the failing command.
