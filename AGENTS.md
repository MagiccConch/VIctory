The cap joins the shader-cache key (`shader_cache.rs::build()` initializes the host first).

Guard arithmetic: when `cap == Some(count + DYNAMIC)` (or `+MIN_DYNAMIC`), the matching `.max(views)` rung always succeeds first, so the plain rungs can never hide a needed guard trim.

## Device removal at world entry: sampler heap never bound (fixed 2026-11-25, commit 363d19d)

- Root cause pinned from the log excerpts: D3D12 debug-layer message **id=1419** — `SetComputeRootSignature: SetDescriptorHeaps must be called to bind a sampler descriptor before setting a root signature with D3D12_ROOT_SIGNATURE_FLAG_SAMPLER_HEAP_DIRECTLY_INDEXED`. Every host pipeline's root signature carries that flag unconditionally (`victory-gpu/src/pipeline/host.rs` root_signature ~line 807, and `victory-shader/src/emit/host.rs:280` for the emit test harness), but `State::bind_heaps` (`victory-gpu/src/draw.rs:836`) bound a sampler heap only when the title had bound one (heaps[1]) whose host copy already existed. With no sampler heap bound: (a) the root-signature set is an invalid call (id=1419, fired at 04:54:35.339 in run 2 with DEBUG on), (b) a translated shader reading `SamplerDescriptorHeap` (SM 6.6 heap-directly-indexed sampling) faults the GPU — run 1's removal 0x887A0001 "after a submission of 1 lists" ~56 s in at world entry (first sampler-heap reads through newly bound pipelines), no breadcrumbs because debug was off.
- The internal HLSL helpers (indirect clamp, twin depth converter, memory prelude, bindless test) embed plain HLSL root signatures (no heap-directly-indexed flags) — never the id=1419 source. The FidelityFX external module sets its own heaps before its root signature (and host_state_lost rebinds after).
- Fix: `descriptor::host::sampler_heap()` (new, descriptor/host.rs after null_sampler) — OnceLock'd shader-visible SAMPLER heap of `HEAP_SAMPLERS` (2048) slots, every slot a plain point-clamp sampler (translated shaders clamp sampler indices below HEAP_SAMPLERS, so every read lands in-bounds; undescribed slots read null, same contract as the view heaps). `bind_heaps` now always binds a sampler heap: the title's host copy when it exists (heap key in host_heaps[1]), else ours (sentinel `OUR_SAMPLERS = usize::MAX - 1`, distinct from `MEMORY_HEAP` = usize::MAX and the `host_state_lost` reset sentinel [usize::MAX; 2]); rebinds when the title's host copy appears later. ## Run 3 (no debug layer) root cause: B4G4R4A4_UNORM render target (2026-11-25)

- The removal reproduced WITHOUT the debug layer (run 3, 06:03:07.257, same 0x887A0001 after 1 list, ~0.8 s after the precursor) — so id=1419 was a real invalid call but not the only one. The precursor in BOTH runs, <1 s before removal: `the host refuses castable formats` → `no host texture` for a 2560×1440 texture, format 115, flags 1.
- Format **115 = DXGI_FORMAT_B4G4R4A4_UNORM** (windows crate Dxgi::Common; 2 bytes/texel, so it is in `element()`'s 2-byte arm). `flags: 1` in victory's ResourceDesc numbering = ALLOW_RENDER_TARGET. D3D12 does not allow render targets in B4G4R4A4 → `CreateCommittedResource3` (castable path, ID3D12Device10) AND the plain `CreateCommittedResource` fallback both E_INVALIDARG → `resource(this).host = None` → the memory has NO host texture; every consumer guards on None (set_targets continue, clear_rtv return, copies skip, SRV null), and the device still removed shortly after.
- Fix (commit 5ecd621, CI 45560228903 green): `resource::supported_flags(format)` — cached `D3D12_FEATURE_FORMAT_SUPPORT` query (RT bit 1, UAV bit 4 of the console flag numbering); `host_desc` drops RT/UAV bits the format cannot serve so the texture is made (flagless). Guards: `draw.rs set_targets` and `list.rs clear_rtv` skip targets/clears whose host texture lacks `D3D12_RESOURCE_FLAG_ALLOW_RENDER_TARGET` (once-warn naming the format). `descriptor::host::typed_store` now delegates to `supported_flags`. Details: typeless formats (family-head test `typeless(format)`) keep their flags (they serve what the family does); the host takes RT or depth, never both, so depth textures lose the RT bit; the optimized clear value is only passed when flags still include RT or depth (D3D12 refuses a clear value on a flagless resource — would have been the NEXT E_INVALIDARG).
- `cargo fmt -p` trap confirmed AGAIN: it reformatted 21 files (+2239/−538) even with file args, because the tree is not rustfmt-clean under rustfmt.toml and CI runs no fmt gate. Recovery: `git checkout -- crates/victory-gpu/src/` then re-applied the semantic hunks by hand (+99/−26 final). Never commit fmt churn.
- Expected next run: the B4G4R4A4 texture exists (log line `texture 2560x1440 f115 flags 0` in the host name tag); warn `a render target the host cannot render to` (or `... clear ...`) appears once; no `no host texture` for it; if the removal persists WITH VICTORY_D3D12_DEBUG=1 the debug layer now names the failing command. ## xcl #84 study: page-lazy shared-heap paging vs our descriptor/host.rs (2026-11-25)

- xcl's design (crates/xcl/src/hle/d3d12x/console_heap.rs, PR #84 by Foniass): ONE shared shader-visible heap for ALL console view heaps; cap = OPTIONS19 `MaxViewDescriptorHeapSize` (else 1<<21). Each console heap gets a "place" (2·n PC descriptors — SRV+UAV pair per slot) in the shared heap, handed out **a page of 256 slots (512 descriptors) at a time on first use** (`page_of` → `reserve_global(page_descriptors(n, p))`, last page exact-sized). `Heap.pages: Vec<u32>` with `UNMAPPED = u32::MAX` sentinel; freed ranges reused via a first-fit `take_range` free list. Laziness is at descriptor-WRITE time (`slot(cpu)` on the shadow-mapped console heap's CPU handle → page reserved, then `publish`/`publish_range` copies per-page runs).
- **Why it works for them and NOT for us:** xcl's translated shaders carry the indirection in the data — the console descriptor's T# word 0 IS the shared-heap index, so slot k of a title heap can live anywhere in the shared heap. Our model is identity-mapped: SM 6.6 heap-directly-indexed `createHandleFromHeap` dereferences heap[slot] on the BOUND heap — slot k must physically sit at host slot k, which forces HostHeap::new to span count+DYNAMIC up front. Page-lazy allocation of a shared pool cannot change where slot k lives, only whether the heap holding it exists.
- Consequence: the direct port does not apply. The analog for our architecture is the two-heap remap (AGENTS.md sketch): SPLIT=1,000,000 (empirical NVIDIA max, confirmed), heap0 = title slots [0, 1e6), heap1 = title slots [1e6, 1179648) + DYNAMIC tail ≈ 441,792 slots ≈ 14 MB — fits the 1M cap with room. xcl-style PAGE-granular scatter would need one root SRV per page range (4,608 pages for the tail alone) — impossible in a root signature.
- Transferable regardless: (1) OPTIONS19 MaxViewDescriptorHeapSize as a cleaner cap source than our PORTABLE_VIEWS+1 probe — but win10-22H2 inbox runtimes may not support OPTIONS19, so keep the probe as fallback; (2) `take_range` first-fit free-list pattern for any future pooled allocation (dynamic-slot cursor reuse); (3) their `census()` (empty/own/other slot classification from raw T# words) is a good diagnostics idea for our mirror report; (4) `publish_range`'s per-page run copying — our sync_heaps already mirrors per-written-page (crate::watch::PAGE), same idea independently.
- Their test worth copying: `large_heaps_get_shared_pages_as_used` — eight 73,727-slot heaps on a 1M-cap shared heap, asserting pages-only allocation and no two slots sharing a PC index. A WARP-runnable analog for us: many large HostHeaps must not multiply commit (our per-heap 2M-slot heaps are ~64 MB each on 32-byte increments — commit pressure item to keep in mind for heap eras).

## Copy-buffer host states (commit 200ff69; the run-5/9 id=538 hang class)

- The copy buffers (shadow host copies of title buffers) were made in COMMON and left there, relying on D3D12 state promotion for every use. Legal only while the buffer stays COMMON: once a heap shader writes it via an unordered view (promoted to UAV — a WRITE state, which does NOT decay at ECL), a later draw reading the same copy as VB/IB is a promotion from UAV — refused by the runtime (debug id=538; retail: mid-run GPU hang 0x887A0006, few lists, no breadcrumbs). Run 5's removal (after 7 lists, 2 min in) and the intro pipeline flood were this.
- Rule source (Enhanced Barriers spec, authoritative restatement of legacy promotion/decay): "Buffers and simultaneous-access textures can be promoted to ANY state (except DEPTH_STENCIL)"; "Resources promoted to a READ state will decay to COMMON when ExecuteCommandLists completes. But not resources promoted to a write state"; cumulative promotion = multiple read bits but ONE write bit.
- Implementation (shadow.rs): `states()` OnceLock+Mutex map keyed by `resource.as_raw()`; `Shadow::taking(buffer, bits)` returns Some((before, after)) iff bits add something AND before != COMMON (from COMMON: promote, record mask, no barrier). `Shadow::as_vertex_data` (VB/IB bind sites draw.rs ~563/~587, VERTEX_AND_CONSTANT=0x1) and `Shadow::ensure_uav` (heap-writing draws draw.rs ~701 via new `Viewed::writing_buffers()` filter on Hull .3=uav, UNORDERED_ACCESS=0x8). `shadow::decay_all()` at the ECL boundary (host.rs submission wrapper, AFTER the wait) drops masks without the UAV bit; masks holding UAV persist (the runtime keeps them). `Shadow::drop` → `forgotten()` only when the shadow OWNS its buffer (`slice.is_none()`); arena-chunk entries STAND (chunk shared by hundreds of copies; a stale COMMON mask on a UAV-state chunk = the same id=538 hang again). Pointer reuse after forget is benign: fresh resource is COMMON, promotion covers, map entry was removed.
- Mask semantics: grows monotonically within/across submissions (UAV|V&CB = 0x9 persists while the write bit lives); transitions are always subset→superset (UAV→UAV|V&CB), never a state change the runtime would reject.
- Tests (shadow.rs mod host_states): fake resource via `transmute_copy` of a stack address + `as_raw()` + `ManuallyDrop` (wrapper never AddRef'd; ManuallyDrop keeps it from releasing through a fake vtable on unwind). Two cases: write-then-read takes the (UAV→UAV|V&CB) barrier once and stays barrier-free after decay (the UAV stands), read-only decays and re-promotes. Note: tests share the global map — each test uses a UNIQUE fake address. CI: run 45675065778 green.
- Cost: VB/IB path +1 map lookup per bind; heap-write path iterates the heap's UAV hulls (already merged per copy) + map lookups. Negligible vs the 13-27 ms hull rebuild.
